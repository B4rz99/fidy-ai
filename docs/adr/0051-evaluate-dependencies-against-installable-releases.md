# Evaluate dependencies against installable releases

Check the newest installable stable release at or below the registry's latest tag. A prerelease
is behind its own stable release even when the version numbers match. SheetJS Community Edition
uses fixed-version distribution tarballs rather than the obsolete npm release. Bound decoded
registry metadata, including long release histories, before parsing it.

A deferral expires at its exclusive UTC instant. An advisory acceptance must name its exact
scanner lockfile path, and the scanner exclusion must match. This prevents one installation's
review from granting an exception to a different lockfile. Missing or invalid scanner inputs fail
the check before evaluating policy.

GitHub Actions use immutable commit SHAs. The corresponding release can be resolved from the
upstream repository without making branch or tag resolution part of execution. Retained Gitleaks
exceptions identify specific historical findings in a public upstream Effect import and copies of
a recorded OpenAPI artifact digest. Keep exceptions scoped to the exact rule, commit, path and line.

Alchemy hashes the site from the app directory. That package retains a local ignore file for
generated Astro output and test artifacts because root-relative ignore rules do not rebase there.

Run Astro checking against the tool's isolated TypeScript 6 install because Astro needs
the JavaScript compiler API that TypeScript 7 does not expose. The isolated JavaScript
lint plugin uses the classic compiler to keep Fidy's Effect diagnostics out of foreign
AST callbacks. Stryker also uses Node for Babel instrumentation and the classic compiler API.

Source scan partitions use only the runners selected by the ordinary change plan. Assign the
complete source scope across those runners so a change-based split cannot hide untouched files
from whole-repository checks. Publication checks treat export provenance separately from import
boundaries and exclude upstream checkouts, ignored output and dependencies as graph roots.
