# Dependency and toolchain freshness audit

**Snapshot:** 2026-08-29T20:34Z
**Repository revision:** `32832c565f023a66b0d375cc59500a0bbd93fdb5`
**Conclusion:** Fidy is **not** on the latest stable version of every declared technology or dependency.

## Method and scope

I inspected the root, application, and isolated-tool manifests, the Bun lockfile, CI actions, Docker/Compose images, and the Cloudflare configuration. The application manifests are `package.json:54-72`, `apps/server/package.json:44-66`, and `apps/web/package.json:23-58`; isolated tools are `tools/depcruise/package.json:6-8`, `tools/mutation/package.json:6-16`, and `tools/crap/package.json:6-11`. The lockfile records the same workspace pins at `bun.lock:1-75`.

For npm packages, “latest” means the npm registry's `dist-tags.latest`, checked on the snapshot date. Package links below point to the authoritative npm packument. For Effect, the stable `latest` tags and the coordinated v4 prerelease channel are reported separately; switching between those channels is not a routine patch update.

Fidy's own checker is useful but is not an “everything is latest” check: it intentionally ignores releases younger than seven days, reports major changes as warnings, and scans manifests only through its bounded manifest patterns (`scripts/check-dependency-updates.ts:73-84,199-232,442-468`). Its current run reported **71 external pins, 0 failures, and 9 reviews**.

## Configuration notes

- `apps/web/cloudflare/wrangler.json:3` uses `compatibility_date: 2026-08-14`. This is a Cloudflare behavior-compatibility choice, not a package version. It is not automatically wrong, but it is not “today's” compatibility date as of this audit.
- The CI and Compose PostgreSQL tags should be treated as infrastructure compatibility pins. Moving from 16 to 18 should be a tested database upgrade, not an automatic freshness edit.
- The current working tree already had unrelated changes (`.agents/skills/opening-a-pr/SKILL.md` modified and `docs/research/free-llm-inference-providers.md` untracked). This audit added only this report and did not alter application or dependency files.

## Recommended order

1. Keep the seven-day admission policy intact; wait for fresh releases to age rather than adding exclusions.
2. Decide whether the project wants the coordinated Effect v4 beta.107 or RC.112 channel; do not downgrade individual Effect packages to their v3/0.x stable tags.
3. Perform the Bun 1.4 migration as one change across `package.json`, CI, Docker, observability expectations, and `bun-types`, following `docs/research/bun-1.4-for-fidy.md`.
4. Review the stable-but-breaking Babel 8 and Stryker 10 upgrades separately.
5. Update the artifact actions, TruffleHog, React Doctor input, and matured npm patches/minors, then run the full verifier and production-image smoke.
