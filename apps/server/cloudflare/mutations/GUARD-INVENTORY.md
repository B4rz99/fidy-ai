# Atomic child guard inventory

One `executeCanonicalMutationUnit` D1 batch contains all ordered children. `canonical_child_guard` CHECK failures prove a **child index**, never an untrusted SQL message. The prepared outcome supplies that child's operation; its owner-supplied `guardRefusal` retains its own premises. The unit delegates domain classification and records only the attributable child's metadata-only refusal after rollback. An unproved child, ambiguous trigger, or forged CHECK text answers `unavailable` without attributing an Audit.

The `budget_audit` day is separate from `auditDayCountExpression`: do **not** silently substitute the shared daily count for its 256-row trigger. A Budget browser child checks only its owner `budget_audit` limit; a PAT Budget child checks only the shared PAT Audit limit. Each check runs inside D1 before that child's success Audit. A preceding child may have changed the applicable count. The capacity check likewise precedes Budget's create trigger under the same D1 lock.

**Change checklist:** when adding a guarded write, a D1 abort trigger, or an Audit table, add its row or extend its owner row here, cover its indexed proof before the trigger (or explicitly fail closed if no sound proof exists), preserve the owner's individual refusal decision, and exercise the mixed-child rollback through the public request path. Never infer which child failed by recounting committed state after the batch rolled back.
