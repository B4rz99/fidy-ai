# Free LLM inference providers

_Research snapshot: 2026-08-29 UTC. Primary sources only. Prices, quotas, model catalogs and promotional programs change frequently; re-check the linked account pages before adoption._

## Short answer

**Yes.** Several providers offer genuinely free API inference, but “free” takes different forms:

- an ongoing free tier with rate limits;
- a monthly allowance;
- a one-time promotional credit;
- free evaluation calls; or
- free model endpoints through an aggregator.

None should be treated as an unrestricted or production-grade capacity guarantee.

## Conditional or promotional access

- **Fireworks AI:** its Startup program says eligible startups can receive credits, but this is an application/eligibility program rather than a universal free tier. Credits expire after one year according to the program page. [Startup program](https://fireworks.ai/startups) · [Credit exhaustion](https://docs.fireworks.ai/faq-new/billing-pricing/what-happens-when-i-finish-my-1-dollar-credit)
- Promotional hackathon, education, startup or referral credits may exist elsewhere, but they are not reliable provider-wide free access. Treat them as temporary credits and verify expiration, payment-method requirements and permitted use directly with the provider.

## Providers that should not be counted as generally free

- **Together AI:** its current billing documentation says it does not offer free trials and requires a minimum $5 credit purchase before API access. [Official billing documentation](https://docs.together.ai/docs/billing-credits)
- **SambaNova Cloud:** its “Free” plan requires adding a payment method and purchasing credits; it is not a zero-cost inference allowance. [Official plans](https://cloud.sambanova.ai/plans)
- **GitHub Models:** GitHub’s current documentation says the service was fully retired on 2026-07-30, including its inference API. [Official retirement notice](https://docs.github.com/en/github-models)

## Recommendation when the objective is maximum free inference

**Start with Mistral Free API as the primary candidate.** It is the only provider found in this review with a clearly advertised recurring dollar allowance (**$10/month**) and no-card API signup. Mistral’s current model pricing lists **Ministral 3 (3B)** at $0.10 per million input tokens and $0.10 per million output tokens, so a fully API-dedicated $10 allowance represents up to 100 million billed tokens in one direction, or about 50 million input plus 50 million output tokens for a balanced workload. [Mistral pricing](https://mistral.ai/pricing/)

That is a budget ceiling, not a throughput guarantee: Mistral says its monthly allowance is shared across Studio, API and Vibe, and exact organization rate limits are shown in the Admin Panel. Confirm the actual limit on Fidy’s account and benchmark the quality of Ministral 3 on Colombian Spanish financial fixtures before committing to it. [Mistral subscriptions](https://docs.mistral.ai/admin/billing-usage/subscriptions) · [Mistral usage limits](https://docs.mistral.ai/admin/billing-usage/usage-limits)

Use **Gemini** and **Groq** as legitimate fallbacks or comparison baselines, but do not rank them above Mistral on total free capacity without checking the live account quotas: Google does not publish exact free-tier quotas on its public rate-limit page, and Groq’s limits are model- and organization-specific. Use **Cerebras** when a one-time $5 trial is enough, and **Cloudflare Workers AI** when the application already belongs on Workers. Cloudflare’s 10,000-Neuron daily allocation is real and recurring, but on its smallest listed LLM it is approximately 4.07M input-only or 0.55M output-only tokens/day; that is useful for small workloads, not an especially large generation budget.

**OpenRouter is genuinely free for its free models**, but it is request-limited rather than a large token allowance: currently 50 free-model API requests/day without purchased credits, or 1,000/day after purchasing at least $10 in credits. `openrouter/free` dynamically selects an available free model, so pin a specific `:free` model when reproducibility matters. This is attractive for testing model alternatives, but less suitable as Fidy’s primary backend because availability, model behavior and downstream provider policies can change.

For Fidy specifically, Mistral’s API documentation says API data is not used for model training, but its privacy documentation says API inputs/outputs may be retained for 30 rolling days for abuse monitoring unless ZDR is activated, and ZDR is available only on paid plans. Therefore, free-tier calls should still use synthetic fixtures until Fidy approves retention, DPA, regional processing and financial-data terms. [Mistral privacy controls](https://docs.mistral.ai/admin/monitor-comply/privacy-data-controls) · [Mistral ZDR](https://docs.mistral.ai/admin/monitor-comply/zero-data-retention)

The Mistral recommendation is a conclusion from the published allowance and price, not a claim that it will outperform every provider’s account-specific quota.

## Model quality for Fidy

The free allowance and model quality are separate decisions. **Ministral 3 3B Instruct** is a serious small model, not a finance-specialized model: Mistral documents Spanish support, structured outputs, function calling, vision and a 256K context window. Mistral’s own evaluation reports the 3B Instruct model at 30.5 Arena Hard, 56.8 WildBench, 83.0 MATH maj@1 and 78.3 MM-MTBench. In the same vendor-run evaluation, it outperforms Gemma 3 4B on WildBench and MATH, while Qwen3-VL 4B scores higher on Arena Hard and MATH. These are useful size-class signals, not independent or finance-specific rankings. [Ministral 3 model page](https://docs.mistral.ai/models/ministral-3-3b-25-12) · [Ministral 3 technical report](https://arxiv.org/html/2601.08584v1)

Cloudflare’s catalog contains substantially larger candidates. `@cf/qwen/qwen3-30b-a3b-fp8` has function calling and reasoning, and Qwen’s 30B-A3B model card describes that model family as 30.5B total parameters with 3.3B activated; `@cf/mistralai/mistral-small-3.1-24b-instruct` has 24B parameters, function calling and 128K context; `@cf/openai/gpt-oss-20b` has reasoning and function calling. These larger models should be treated as higher-capability candidates for difficult or ambiguous financial text, but no comparable independent FinanceBench score for the current hosted variants was found. [Cloudflare model catalog](https://developers.cloudflare.com/workers-ai/models/) · [Qwen3 model card](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507) · [Cloudflare Mistral Small 3.1](https://developers.cloudflare.com/workers-ai/models/mistral-small-3.1-24b-instruct/) · [Cloudflare GPT-OSS 20B](https://developers.cloudflare.com/workers-ai/models/gpt-oss-20b/)

For Fidy, the first practical comparison should be:

1. **Ministral 3 3B Instruct** for maximum throughput and structured extraction.
2. **Cloudflare Qwen3 30B A3B** as the likely quality-per-Neuron challenger; it has a much larger total model while retaining roughly 3B active parameters.
3. **Cloudflare Mistral Small 3.1 24B** as a quality ceiling among the Mistral candidates, accepting substantially lower free volume.

The Qwen3 and Mistral Small candidates consume the same daily Neuron pool but not the same number of requests: Cloudflare’s published rates put Qwen3 30B A3B at 4,625 input and 30,475 output Neurons per million tokens, versus Mistral Small 3.1 at 31,876 input and 50,488 output Neurons per million. Larger does not mean more free inference; it means fewer calls for potentially better answers. Some catalog models may also require Workers Paid, so verify access on the actual account before designing around one. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) · [Workers AI exhausted-allocation error](https://developers.cloudflare.com/workers-ai/platform/errors/)

### Finance benchmarks and their limits

There are useful finance benchmarks, but none is a close proxy for Fidy’s Colombian personal-finance ingestion:

- **FinanceBench** contains 10,231 open-book questions about public-company filings, with 150 annotated examples released publicly. It tests retrieval, evidence grounding and financial QA—not turning a Colombian bank notification or receipt into a `Transaction`. Its authors reported that GPT-4-Turbo with retrieval incorrectly answered or refused 81% of their sampled questions, so even strong general models should not be assumed reliable in finance. [FinanceBench repository](https://github.com/patronus-ai/financebench) · [FinanceBench paper](https://arxiv.org/abs/2311.11944)
- **FinQA** contains 8,281 QA pairs over financial reports, tables and text, with annotated reasoning programs. It is useful for numerical reasoning over statements, not personal transaction normalization. [FinQA repository](https://github.com/czyssrs/FinQA) · [FinQA paper](https://aclanthology.org/2021.emnlp-main.300/)
- **TAT-QA** contains 16,552 questions over 2,757 hybrid financial-report contexts and tests extraction plus arithmetic/comparison reasoning. Its published TagOp baseline reached 58.0 F1 versus 90.8 F1 for experts, again demonstrating that financial QA is difficult. [TAT-QA repository](https://github.com/NExTplusplus/TAT-QA) · [TAT-QA paper](https://aclanthology.org/2021.acl-long.254/)

Fidy should therefore create a small, versioned **es-CO ingestion evaluation set** rather than select a provider from generic scores. Score exact `Money` and `Currency`, direction, date/time, `Counterparty` precision, `Category` accuracy, schema validity, correct `NeedsReviewItem` abstention, and hallucination rate. Include Colombian formats and descriptors such as `PSE`, `Nequi`, `DaviPlata`, `RETIRO ATM`, `ABONO`, `DÉBITO`, `GMF/4x1000`, refunds, reversals, duplicated notifications and ambiguous bank descriptions. Keep Money arithmetic and validation in deterministic server code; the model should propose normalized facts, not become the authority for financial truth.

## Unresolved questions

- Exact free quotas and model availability are account- and provider-specific and can change without this report changing.
- The providers do not expose a uniform definition of “free”; an implementation decision should record whether it needs recurring capacity, no-card signup, a fixed trial budget, or a privacy/processing commitment.
- Before production use, provider-specific DPA, retention, training, incident, region and financial-data terms still need review; free pricing alone does not answer those questions.
