Issue #137 · agreed follow-up design

Hosted agent continuity, atomic batches, bounded retries, and provider caps

A high-level view of A7, A9, A11, and A13: preserve model continuity only within a turn, authorize and execute canonical mutation batches atomically, retry one transient provider failure inside the existing round deadline, and project the remaining host tool budget into every OpenAI request.

Decisions at a glance

A7

Transient continuation

Replay assistant text accompanying tool calls during the same turn. Do not persist it as if it had been delivered to the User.

A9

Atomic mutation batch

Preflight every call, request one exact batch confirmation, then let the canonical batch perform authoritative checks and execution in one PostgreSQL transaction.

A11

One bounded retry

At most two provider attempts share one 30-second model-round deadline. Retry only a retryable AiError.

A13

Remaining tool budget

Send OpenAI the remaining turn budget as max_tool_calls. Disable tools when the budget reaches zero.

A7 · transient assistant text continuity

Provider responseOrdered text and tool-call parts.
AcceptValidate finish reason and decode calls.
Retain in memoryKeep original assistant-part order for this turn.
Execute toolsAppend canonical tool calls/results durably.
Next promptDurable history plus transient continuation.
Not persisted: accompanying text is not an AssistantTranscriptEntry unless it was actually delivered to the User. It disappears when the turn ends.

A9 · one confirmation, one atomic mutation batch

Stage Guarantee Failure behavior
Initial preflight Every call is a canonical mutation and decodes, authorizes, and validates at challenge time. Execute nothing; give an actionable explanation.
Confirmation One digest binds the exact ordered calls and arguments; challenge is expiring and single-use. Reject stale, altered, or replayed confirmation.
Atomic execution Authoritative authorization, precondition, and domain checks run with all canonical mutation effects and durable job inserts inside one PostgreSQL transaction. Any child failure rolls back every child effect and becomes an actionable User explanation.
External work A committed durable job survives crashes and is retried by a worker. The external action is not falsely described as transactionally reversible.
Mutation invariant: direct external side effects cannot be rolled back by PostgreSQL. A canonical mutation that needs external work atomically persists durable intent for post-commit execution; it cannot opt out through an eligibility flag.

Required architecture changes

  • Classify every canonical operation explicitly as a query or mutation.
  • Publish operations.executeAtomicBatch normally on HTTP, OpenAPI, typed client, MCP, CLI, and the hosted-agent toolkit.
  • Derive a bounded tagged union of every canonical mutation input from the catalog; structurally excluding the batch operation from that child union makes recursion impossible by schema.
  • Put every canonical mutation behind a reusable implementation that accepts a transaction-scoped SqlClient.
  • Make individual operations and the batch operation call those same implementations.
  • Preserve per-child authorization, Subscription, quota, audit, validation, and typed failure semantics.
Nothing hidden: the batch is a normal visible canonical operation. The schema—not surface filtering—prevents nested batches and excludes canonical queries.

A11 · retry inside one model-round deadline

Policy

  • Two attempts maximum.
  • Retry only AiError.isRetryable.
  • Normalize optional retryAfter to Effect Option.
  • Use a small jittered fallback delay when absent.
  • Delay and both attempts share the same timeout.

Default timing

  • maxModelRoundMillis = 30_000.
  • The configured schema permits up to 120 seconds.
  • Provider retry does not consume an Agent iteration.
  • No retry starts when the delay plus minimum attempt window cannot fit.
  • An overall turn deadline remains separate follow-up policy.

A13 · translate a turn budget into request caps

flowchart LR
  B[Host maxToolCallsPerTurn = 12] --> R1[Round 1 remaining 12\nmax_tool_calls: 12]
  R1 -->|accept 4 calls| R2[Round 2 remaining 8\nmax_tool_calls: 8]
  R2 -->|accept 5 calls| R3[Round 3 remaining 3\nmax_tool_calls: 3]
  R3 -->|accept 3 calls| F[Finalization round\ntool_choice: none]
  F --> U[Final User reply]
Defense in depth: OpenAI receives the request cap, but the host still validates the aggregate accepted-call count. User quota, fair-use, and monetary cost controls remain separate modules owned by issues #30 and #35.

Invariant checklist

Invariant Owner
Text accompanying tool calls is replayed during the turn but never mislabeled as delivered Transcript text. A7 continuation
No generated call executes before whole-response preflight and confirmation settlement. A9 preflight
Confirmation binds exact ordered canonical operation ids and encoded inputs. A9 confirmation
Eligible batch execution commits all database effects or none. A9 atomic batch
Provider retries cannot extend a model round beyond its existing deadline. A11 retry controller
Provider cap never exceeds the host's remaining tool budget. A13 projection
Host aggregate enforcement remains authoritative even when provider caps are sent. AgentService
