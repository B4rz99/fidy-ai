# Durable execution inventory

This is the baseline classification required by
[ADR 0024](../adr/0024-effect-durable-execution.md). It audits production server source at
`1c04557796e2b63ee26d1f1aaa414526032b099d` (the parent of the pattern-documentation commit). Tests,
fixtures, development seed code, release tooling, and the interactive REPL are excluded unless they
prove a production mechanism. Update the affected row during each migration.

## Dispositions

Every item has one disposition:

- **Effect durable execution** — replace execution-only claims, leases, retries, polling, durable
  waits, or cross-transaction serialization with the Effect facility named in the row.
- **Effect process-local coordination** — keep an Effect primitive because losing its state on
  restart and applying it independently per replica cannot violate correctness.
- **Database constraint or atomic statement** — retain PostgreSQL coordination embedded in the
  write that enforces the invariant.
- **Retained transactional lock** — retain a row or transaction advisory lock around one short
  commit-time invariant; no network work occurs while held.
- **Deliberate existing scheduling** — keep an immediate-at-startup, repeat-safe maintenance loop
  when missing one tick only delays cleanup; issue #469 owns the final consolidation.

“Replace” means expand–migrate–contract under the linked ticket, not immediate deletion by this
audit.
