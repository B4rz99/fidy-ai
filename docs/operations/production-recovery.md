# Production recovery

Start with the protected native application run and its artifact. Record the exact trunk SHA, stable and candidate Worker deployment/version IDs, contracts and taxonomy, and five namespace identities and histories. Use aggregate state and the private operational health signals to distinguish an unreachable endpoint, unobserved owner work, a failed provider read and a pending Workflow. Keep credentials and financial material in their private owners. [Release procedure](production-releases.md)

Keep ordinary admission closed during first installation, maintenance and staged acceptance. The independently guarded host staging operation may resume after a partial alias or Access update only when every visible resource is either the approved previous state or its exact desired state. An occupied hostname, changed identity, ambiguous queue or Workflow state, or failed provider read requires inspection before retry.

A code rollback is possible only for the captured native pair when both code directions were tested against retained storage and the caller still observes the expected serving pair. The protected release workflow records eligibility, promotes the tested candidates and checks the actual installed application. It can restore the tested target on failed promoted verification. A rollback changes Worker routing while the same SQLite namespaces, retained alarms, queues, workflow instances, R2 bytes and provider-side effects continue to exist. Use the exact captured receipts and current Cloudflare state when investigating interrupted promotion. Keep recovery closed if a compatible target cannot be proved.

Allow existing owner alarms and Maintenance to resume durable work using the original operation identity. Verify the actual owner receipt, current authority and provider observation before reporting settlement. An ambiguous payment or send uses its existing reconciliation path. Preserve the fenced incumbent dead-letter queue, including its backlog, until the separate retirement authorization. Keep new release queues independent.

For erasure, inspect the Erasure owner's case and original custody scope with its dedicated authority. Actual deletion, independent R2 disposition and provider custody observations must agree before recording completion. An unresolved custodian remains pending across the platform recovery horizon. The retired shared D1 database backup and registry are outside native code rollback.
