# Private SQLite inspection and repair

Run `fidy storage` from a trusted interactive terminal. In a checkout use the repository-pinned Bun with `bun run cli storage`. The command reads one JSON object from the terminal, opens the dedicated Cloudflare Access application with cloudflared, submits one bounded POST, and displays the owner's bounded response. The operator needs no database credential. Keep assertions, case or operation IDs, and identifying details out of tickets, shared logs and shell history.

The Production environment variable `STORAGE_OPERATOR_EMAIL` assigns the single approved human for `/internal/storage-operations`. An empty assignment disables the capability. The application, exact-email allow policy and session have a 15-minute lifetime limit. Core independently verifies the signed assertion, audience, issuer, operator and deadline. Inspection is the default. Exact repair also requires the separately approved deployment setting `STORAGE_REPAIR_ENABLED=enabled`. Deployment must use a distinct generated audience from recovery, billing, Price publication, sample review and erasure. Check the deployed path, audience, single human policy, session duration and bound Core version before exercising the capability. The reviewer assignment confers sample review only.

## Find the affected owner

Enter `{"action":"inspect","owner":"maintenance"}` for the traversal progress. Check the release, schema version, storage bytes and ceiling, last attempt, last successful observation, wrap and coverage age. Inspect a fixed `directory`, `pricing` or `erasure` owner in the same way. For a specific User use `{"action":"inspect","owner":"user","userId":"<UserId>"}`. Replace placeholders with the affected opaque IDs from the restricted evidence. A missing measurement or a failed transport leaves the scope unknown. Report the specific unavailable owner and its dependent capabilities.

A Price publication miss means no receipt was observed. Never infer a cancelled provider send, identity handoff or completed erasure from absence.

## Monitoring and evidence

The private minute watchdog records attempted and successfully observed checks separately. It measures traversal age and the oldest registered User still awaiting a successful schema-bearing observation. It warns at five elapsed minutes and escalates at ten. A failed shared check or deterministic schema failure is critical at detection. Successful batches report observed schema versions/releases and storage bands. Missing or overdue alarms and bounded uncertain-operation counts/ages are metadata. A count of 33 marks a truncated family sample, and an absent age remains unknown. Inspect the original User or shared owner to verify recovery.

Use the existing **Fidy owner health — timestamped observations** saved search and the combined attention monitor. The account evaluates over ten minutes every ten minutes, with thirty-minute repeats. Alert delivery can lag detection. Query counts include only successful observations. A partial sweep or a repaired alarm cannot establish global health or completed work. See [Cloudflare background monitoring](cloudflare-background-work.md).

Successful operation admission records the operator, action, verified target, timestamp and outcome privately at the owner. Receipts contain no request body or Secret. Target-bound evidence goes away with its original row or User purge. Generic store receipts and other operation evidence have bounded cleanup against a 365-day retention horizon in owner checks. Erasure observations follow the independent case lifetime. Per-User observation timestamps update the existing registry row and its index for each observed registered User per check. Include those writes in the watchdog benchmark.

For structural samples the authorized human uses `fidy sample-review review`, `retry` and `withdraw`. Preserve original deadlines, the previewed bytes and the independent withdrawal fence. Record actual human approval and platform policy checks separately from signed local fixtures. [Sample review](ingest-sample-review.md)

Each page is released only with a new local Audit reference. An expired browser must establish fresh authority before continuing with its cursor. Storage operations reveal no Transaction content.
