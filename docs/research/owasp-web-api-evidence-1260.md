# Web, API and CLI implementation evidence — #1260

Assessed 2026-10-13 against the merged #1259 implementation, commit
`01a63f1c414b1877a9abd6c68d8b8de2fb840af6`, and the working tree for #1260.
Category names/editions come from
[the verified reference inventory](owasp-reference-verification-2026-10-13.md).
This is a bounded implementation assessment, not certification, penetration-test
coverage of every endpoint, or an ASVS verification level. Web includes its server,
public ingress, background and deployment boundaries. CLI is assessed by its actual
boundaries rather than by inventing a separate Top 10.

**Verified scoped** means the specified control was traced into implementation and
its cited negative assertions inspected; it does not mean every mitigation in an
entire category is verified. **Partial** identifies a concrete limitation.
**Accepted risk** is not a fix. A previously passing CI run is explicitly separated
from the targeted reruns below. None of the rows relies on a policy citation alone.

## CLI, background work and infrastructure applicability

CLI participates in A01/API1, A07/API2 and API5 through the same canonical server
controls, not through local CLI flags. E12 directly verifies local filesystem refusal
before native credential access; E7/E11 illustrate the shared destination/secret
handling requirements, but browser tests are not substitutes for CLI transport tests.
The previous #1259 CI passed native packaging and OS store conformance; those OS
runs were not repeated here. CLI distribution still inherits A03's dependency risk.
There is no separate CLI web-cookie/CORS control to certify.

Background work inherits owner identity, current authority, bounded work and atomic
commit, rather than trusting a Queue body as fresh authorization.
`apps/server/cloudflare/queue/runtime.ts::makeCoreQueue` and its owned dispatch
implementation re-read authoritative work. Inspected `queue/failure-isolation.test.ts`
**“retains statement ownership and expiry guards while acknowledging confirmed
duplicate handoffs”** checks owner/expiry rejection and duplicate handling;
**“stops later handoffs on interruption without acknowledging an ambiguous in-flight
create”** checks cancellation leaves uncertain work unacknowledged. These were not
rerun here; use the prior passing #1259 CI and the separate background assessment.

Infrastructure evidence E10 is generated topology/configuration testing. It establishes
what deployment is intended to apply, not that the live Cloudflare account currently
matches it. No deployment, billable provider test, operator email, or production
credential change was performed during this review.

## Concrete residuals and ownership

Outstanding A09/live operational evidence and the accepted supply-chain exception are
tracked in [#1262](https://github.com/B4rz99/fidy-ai/issues/1262).

- **A09 security alerting is partial, not absent logging.** Audit tests prove bounded,
  private records; operational health owns D1 failure, Workflow/Queue and durable-work
  alerts. `docs/operations/cloudflare-background-work.md` explicitly records that
  Worker exception/CPU-memory-limit and callback-rejection counters no longer have
  automatic email after Tail removal. Neither a safe telemetry record nor a Queue
  backlog alert establishes detection of an authentication attack or callback-rejection
  spike. The repository's launch checklist already requires an explicit implementation
  or launch decision for this gap. Owner: runtime operational-health and production
  operator. Completion needs fixed-cardinality signal/threshold policy, failure-safe
  delivery and tests, then actual configured-channel receipt evidence. Reintroducing
  unrestricted request/Tail logging would conflict with the privacy boundary.
- **A03 accepted braces risk.** `dependency-policy.json` records
  `GHSA-vfj7-8cjw-p6xm` in the required shadcn development chain with an exclusive
  `2026-10-17T00:00:00Z` expiry; `docs/operations/security-hardening-1250.md` documents
  the matching SCA exception and restricted trusted inputs. This review did not
  re-query upstream availability or renew that exception. Owner: dependency/security
  gate. Resolve through a reviewed fixed chain after its seven-day admission window,
  remove both exceptions and rerun SCA; if no admitted fix exists, explicit reassessment
  is required before expiry. The current finding remains accepted, not remediated.
- **API9/live operations.** Generated repository inventory is concrete evidence, but
  cloud account inventory, actual header/WAF drift, operator alert receipt and account
  spend notifications need production-owner records. No local test may substitute
  for them. Provider activation and OAuth launch decisions remain existing gates.

No new exploitable implementation flaw was demonstrated in this bounded follow-up.
No production code was changed merely to convert an evidence limit into a green
status. The deliverable closes the missing category-to-control/test mapping and makes
its remaining limits explicit; it does not close the residuals above by documentation.
